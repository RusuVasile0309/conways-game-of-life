## What Went Well

**`RuleSet` placed in `libs/types` — correct boundary decision with immediate payoff.** The architecture decision to put the interface in `libs/types` (not `libs/sim`) meant Story 8.2 imported `RuleSet` from `@conways-game-of-life/types` with zero boundary violation. If it had lived in `libs/sim`, the web app would have hit an ESLint error on day one. This is the architectural reasoning paying off in practice.

**Behavioral divergence test in 8.1 proves real divergence.** The B6 6-neighbor grid test that produces different outputs from `conwayRules` and `highLifeRules` on the same input is a real behavioral assertion — not a smoke test. It would catch a regression where HighLife accidentally inherited Conway's birth conditions.

**Code review process caught both functional gaps and pre-existing debt.** Story 8.1: `.js` extension missed on in-scope `conway.ts` edit, missing live-cell-6-neighbor test, empty-grid and determinism gaps. Story 8.2: keyboard navigation entirely absent from custom dropdown (M3), DEFAULT_WIDTH silent regression (M4), zero unit tests for the component (L2). None of these would have shipped if review wasn't a mandatory gate.

**`ruleSetRef` pattern correctly applied.** Closing over `ruleSet` state in `onTick` would have created a new loop identity on every rule change. Using a ref mirrors `genPerSecRef` and keeps the rAF loop stable. The precedent was followed correctly.

**Tab-order E2E subtask — team agreement from Epic 7 retro honored.** Story 8.2 included the `a11y.spec.ts` update as an explicit subtask. It was executed. This agreement now has two confirmed data points (Epic 5 pattern → Epic 8 application).

**Custom dropdown was the right call.** Native `<select>` renders inconsistently: iOS Safari wheel-picker, Android modal sheet, Firefox ignores CSS styling. The pivot to a custom dropdown was motivated by observable, real browser behavior. The final component — ARIA pattern correct, keyboard nav complete (`ArrowDown/Up/Home/End/Enter/Escape`), `aria-activedescendant` virtual focus, click-outside close, disabled state — is production-quality work.

## Challenges

**Native → custom dropdown pivot didn't carry its full obligation list.** The story dev notes originally said to use a native `<select>`. When the pivot to a custom dropdown was decided, the new requirements it carried — keyboard navigation, `aria-activedescendant`, full ARIA listbox semantics — were not written into the ACs at pivot time. Code review caught the delta (M3). A mid-story design change needs an explicit "what new ACs does this approach require?" check before continuing.

**`.js` CLAUDE.md action item: three epics old, still unresolved.** Flagged in Epic 5 retro, recommitted in Epic 7 retro, Epic 8 ends with it still absent from `CLAUDE.md`. It surfaced again in Story 8.1's code review — `conway.ts` was modified in-story and the import still lacked `.js`. The rule is documented in memory files and per-story dev notes; it needs to be in `CLAUDE.md` where it's loaded on every session.

**Action items requiring out-of-story file edits consistently slip.** The Tab-order subtask succeeded because it was embedded in story ACs. The CLAUDE.md edit failed because it was a free-floating "do this before next epic" task. This is not a people problem — it's a process design problem. If an action item isn't attached to story structure, it doesn't ship.

**Story 8.2 scope expanded significantly beyond original ACs.** The mobile UI polish (XIcon, DiceIcon, SizeForm inline label), PatternSelector height fix, and DEFAULT_WIDTH correction were not in the ACs. They're good improvements, but the DEFAULT_WIDTH bug was found opportunistically — as a side-effect of being in `page.tsx` — not through systematic verification against `project-context.md`.

**WCAG AC not formally added to Story 8.2.** Epic 7 retro action item 2 called for WCAG contrast verification as an explicit AC. The colors used in 8.2 (`cyan-600`, `neutral-300`) match the existing palette that passed prior audits, but no formal contrast check AC was written. The intent was partially met, the process commitment was not.

---

## Key Insights

1. **Design pivots mid-story need an AC delta analysis.** The question to ask: "what new requirements does this changed approach carry?" Running that check before continuing would have surfaced the keyboard nav and ARIA obligations at pivot time, not at code review.

2. **Process agreements only stick when embedded in story structure.** Agreements that get converted to story subtasks (Tab-order E2E) get executed. Agreements that stay as free-floating action items (CLAUDE.md edit) slip. The system to enforce this: when an action item requires a file edit, that edit must be the first subtask of the next story created.

3. **The `.js` rule needs CLAUDE.md, not just memory.** Three epics of friction from one missing config rule. The fix is a single paragraph addition. The cost of not doing it compounds every sprint.

4. **Code review is the primary quality gate — it works.** Both stories had real issues caught. The goal for future work is to push more of that surface area into story ACs so review confirms rather than discovers.
